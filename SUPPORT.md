# Getting Support

For usage questions, first consult the README, package help, pkgdown articles,
and the troubleshooting/glossary vignettes.

For a reproducible bug, open a GitHub issue using the bug-report template and
include the SEMANTICA version, `sessionInfo()`, operating system, backend/model
identifiers, relevant configuration, the smallest reproducible example, and the
complete error message. Remove credentials, participant data, and private paths.

For feature requests, explain the user problem and desired behavior rather than
prescribing an internal implementation. Methodological changes should identify
the scientific/statistical rationale and relevant literature where possible.

Security-sensitive reports should follow `SECURITY.md` instead of being posted
publicly.
